## Binding and interaction contract

This phase changes data binding only. Visual classes stay as shipped.

1. **Delete `mockLeaveBalance`.** Render `leaveBalance` from `useDashboardData`. Never fall back to 10/20/10 or 5-used mock rows (D-09, D-10; BAL-01).
2. **Uncomment the empty branch** when `!leaveBalance \|\| leaveBalance.length === 0` after loading (and on fetch error). Card chrome stays visible (D-08).
3. **Display order:** vacation, then sick, then personal (D-12). Sort/filter the fetched array before map. Extra GET types (maternity, paternity, bereavement, unpaid, other) are not rendered this phase — keep the display-name/color maps but do not output those rows.
4. **Remaining number** uses the `remaining_days` column, not `total_allowance - used_days` (D-11). Remove the local `remaining` subtraction.
5. **Progress value** stays `total_allowance > 0 ? (used_days / total_allowance) * 100 : 0`. Do not drive the bar from `remaining_days`.
6. **Loading:** existing three-row `animate-pulse` skeleton (gray-200 `h-4` + `h-2`). Title “Leave Balance” + Calendar icon stay visible. Do not swap for `Skeleton` primitive or a spinner (D-09).
7. **Fetch error:** `useQuery` for `['leaveBalance', user.id]` must toast `Failed to load leave balances` via `sonner` (the existing `fallbackError` string) and pass empty/undefined balances so the card shows empty copy. Do not keep last mock. Reuse the existing `Toaster` in `session-provider.tsx` — do not mount a second toaster.
8. **Zero remaining is populated, not empty.** A row with `remaining_days === 0` still shows the bar and `0 days remaining`. Empty copy is only when there are no rows after self-heal (D-08).
9. **Partial rows:** if GET returns only some of the three types (D-15 skip missing policy), render only those rows in vacation → sick → personal order. Do not invent 0-allowance bars for missing types.
10. **Query key** stays `['leaveBalance', user.id]`. Fetch stays `GET /api/leave-balances` with `credentials: 'include'`. Do not put remaining-day reads on the browser anon client.
11. **No new dashboard layout.** Card stays first in the Overview left column (`lg:col-span-3`). Do not add the card to Requests or Calendar tabs.
