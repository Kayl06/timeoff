<interfaces>
Export from invite-auth.ts (in addition to inviteOwnerRejectStatus):

ALREADY_IN_COMPANY_ERROR = That email is already in this company.
EMAIL_EXISTS_ERROR = An account with this email already exists. Sign in, or ask your admin for an invite.

inviteCreateConflict(input): string | null
input.existingUserCompanyId: string | null | undefined — company_id from a users row matched by email globally, or null/undefined if none
input.ownerCompanyId: string — the inviting owner's companies.id
input.pendingInviteInCompany: boolean — pending company_invites for this email AND this company

Return ALREADY_IN_COMPANY_ERROR when pendingInviteInCompany is true, or when existingUserCompanyId equals ownerCompanyId.
Return EMAIL_EXISTS_ERROR when existingUserCompanyId is a non-empty string not equal to ownerCompanyId.
Return null when there is no existing user and no pending invite in this company.

POST users lookup: supabase.from('users').select('id, company_id').eq('email', email).maybeSingle() with no company_id filter. Pending invite lookup stays company-scoped as today.

409 JSON: { error: &lt;conflict string&gt; } status 409. Do not include acceptUrl.

Dialog already sets emailError from payload.error on 409; import EMAIL_EXISTS_ERROR / ALREADY_IN_COMPANY_ERROR only if needed as fallback. Keep sonner for non-409 failures.
</interfaces>
