## Spacing Scale

Declared values (must be multiples of 4). Match existing auth pages (`p-4`, `space-y-2`/`4`/`6`, `gap-4`).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-error-text gap (`mr-1`), password-requirement rows (`space-y-1`) |
| sm | 8px | Label-to-field (`space-y-2`), inline control gaps (`space-x-2`) |
| md | 16px | Page padding (`p-4`), field-group gaps (`space-y-4`, `gap-4`), logo margin (`mb-4`) |
| lg | 24px | Card content stack (`space-y-6`), `CardHeader`/`CardContent` padding (`p-6`) |
| xl | 32px | Unused on auth cards this phase |
| 2xl | 48px | Input/CTA height (`h-12`); 48×48 “TO” mark |
| 3xl | 64px | Unused this phase |

Exceptions: auth primary fields and primary CTAs stay `h-12` (48px) to match shipped sign-in/sign-up — not the shadcn default `h-9`. Icon-only password-toggle hit area is the 48px-tall input row, not a separate 44px control. Do not add a 44px exception. The toggle must have an accessible name: `aria-label` “Show password” when hidden, “Hide password” when visible. Carry the same labels onto accept-invite if it clones the signup password field.

Focal point (primary screen hierarchy — Dimension 2):
- Signup: the `Create company` CTA is the focal point (TO mark is brand chrome, not a competing CTA).
- Invite dialog: the `Send invite` CTA is the focal point until success; then `Copy invite link`.
- Accept-invite: the `Join company` CTA is the focal point.
- Invite required: the `Create a company` primary button is the focal point.

## Typography

Inter. Phase 1 surfaces (auth cards + invite dialog) use exactly these four sizes and two weights. Do not add `text-3xl` on auth/invite. Do not restyle dashboard `text-3xl` welcome headings (out of scope).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`) | 400 | 1.5 |
| Label | 14px (`text-sm`) | 400 | 1.5 |
| Heading | 24px (`text-2xl`) | 700 | 1.2 |
| Display | 20px (`text-xl`) | 700 | 1.2 |

Display is the “TO” mark lettering only. Helper/muted copy (`text-gray-600`, divider “Or continue with”) is Label size at weight 400. Password-requirement rows stay `text-xs` (12px) — existing signup widget; do not restyle it, and do not introduce 12px on new Phase 1 copy.

Keep shipped shadcn `Button` / `Label` `font-medium` (500) on those primitives. Do not add a third weight in new Phase 1 text (headings stay `font-bold` / 700; body/labels/descriptions stay 400).

## Color

Tokens from `:root` in `apps/web/src/app/globals.css`. Auth pages keep the existing page wash `bg-gradient-to-br from-blue-50 via-white to-purple-50`. New/changed controls use CSS variables (`bg-primary`, `text-primary`), not ad-hoc `blue-600` / `sky-600` (signup currently mixes those; Phase 1 signup/invite/accept must match sign-in’s `from-primary` CTA).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` (`--background` / `--card`) | Auth card fill (`bg-white/80`), inputs, dialog surface |
| Secondary (30%) | `#F5F5F5` (`--secondary` / `--muted`) | Muted chips, password-strength empty bars (`bg-gray-200`), dashboard page `bg-gray-50` (unchanged) |
| Accent (10%) | `#8B2F9D` (`--primary` hsl `290 54% 40%`) | See reserved list below |
| Destructive | `#EF4444` (`--destructive` / existing `text-red-600` / `border-red-500`) | Inline field errors and auth-error icon only |

Accent reserved for: primary submit buttons (“Create company”, “Send invite”, “Join company”, “Sign in”); the 48×48 “TO” mark fill; `timeoff.hr` nav wordmark (existing); focus ring on those primary CTAs. Not for Google outline buttons, not for “Sign in” / “Forgot password?” text links (those stay `text-blue-600` as on shipped sign-in), not for every interactive element.

Foreground on primary buttons: `#FAFAFA` (`--primary-foreground`). Body text on auth cards: `#0A0A0A` / `text-gray-900` headings, `text-gray-600` descriptions (`#737373` muted).

## Surfaces and interaction contract

Scope: auth + owner invite. Do not rebuild `/(admin)/users` (PROJECT.md). Do not add a dashboard header CTA next to `LeaveRequestForm`.

| Surface | Route / host | Who sees it | Change vs shipped |
|---------|--------------|-------------|-------------------|
| Create company | `/auth/signup` | Anonymous | Add required Company name (`Building2` icon, `h-12` input) **above** Google; retitle; primary CTA “Create company”; Google allowed only if company name is non-empty (pass name in OAuth `callbackUrl` / state). Existing name/email/password/terms stay |
| Sign in | `/auth/signin` | Anonymous | Restore footer link to signup with “Create a company”. Google for unknown emails must land on InviteRequired — no auto-insert into a global `employee` pool |
| Accept invite | `/auth/accept-invite?token=` | Anonymous | **New** page, clone sign-up Card chrome (`min-h-screen` gradient, `max-w-md`, glass Card, TO mark). No company-name field. Credentials join or Google join bound to that invite’s company only |
| Invite required | `/auth/error?error=InviteRequired` | Anonymous after blocked Google | New `getErrorDetails` branch; same error Card |
| Invite teammates | `DropdownMenuItem` on `Navigation` avatar menu | Owner only | New item between Settings and Log out. Opens `Dialog`. Hidden for non-owners. Do not implement Settings |
| Forgot / reset | `/auth/forgot-password`, `/auth/reset-password` | Anonymous | **No visual change** (Phase 6) |

### Interaction rules

1. First credentials signup creates the company and makes that user the owner, then redirects to `/auth/signin` (existing success path) with the success toast above.
2. Google on `/auth/signup` does not run until company name is filled; Google on `/auth/signin` does not create users; Google on `/auth/accept-invite` joins that company only (TENANT-05).
3. Invite dialog: email field plus a pending/sent invite list for this company. One email per Send invite. After success, show helper + read-only link + Copy for that invite, and append/keep the row in the list. Empty list uses `No teammates yet`. Closing the dialog is enough; no confirmation for cancel (not destructive). Do not build `/(admin)/users`.
4. Invitee opens the link, completes accept-invite, lands on `/dashboard`. They never see a company picker.
5. Non-owner: no Invite teammates item. Hitting an invite API returns the Unauthorized copy.
6. Loading: disable submit + Google; show `Loader2` in the active button. Do not blank the Card.
7. Focus: first field on signup is Company name; on accept-invite, First name (or Google if they only use OAuth). Dialog focus on Work email.
