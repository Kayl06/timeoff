## Phase Goal

**As a** signed-in employee of Company A, **I want to** request and update leave using my signed-in session, **so that** Company B cannot read or change our people, requests, balances, calendars, notifications, or audit, and someone holding only the public API key cannot operate without a tenant session.

<assumption_delta_decision>
noun: company_id / session.user.companyId
decision: no-change
rationale: Phase 1 already made users.company_id NOT NULL the tenant identity. This phase enforces that same noun via JWT claim and later RLS. Do not add a second identity (org_id, tenant_id, workspace_id) alongside users.company_id.
</assumption_delta_decision>

<objective>
End-to-end tracer: signed-in POST/GET own leave requests through getServerSession, minted HS256 JWT, request-scoped IDatabaseService, and the existing createLeaveRequest mutation swapped to fetch.

Purpose: AUTHZ-01 happy path on one resource before remaining routes and RLS. Proves BFF architecture end-to-end.
Output: env secrets required; DatabaseServiceFactory.create; createTenantDatabaseService; GET/POST /api/leave-requests; dashboard create via BFF.
</objective>
